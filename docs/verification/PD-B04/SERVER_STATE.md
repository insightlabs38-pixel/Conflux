# PD-B04-T02 — server-state layer

Library: `@tanstack/react-query` v5 (mature, React-19 compatible, covers caching, dedupe, invalidation, retry, cancellation, optimistic updates). One `QueryClient` per `App` (injectable for tests/embedders: `<App queryClient={...} />`).

| Concern            | Where                                          | Behavior                                                                                                                                                                                     |
| ------------------ | ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Transport seam     | `src/web/lib/api.ts` `apiRequest` / `ApiError` | credentials, JSON body, `AbortSignal`, status + server `detail` in `ApiError`, caller-supplied `describe`; the generated typed client replaces the internals in T03 without touching callers |
| Defaults           | `src/web/lib/query.ts` `createQueryClient`     | `staleTime` 30 s, `gcTime` 5 min, no refetch on focus/reconnect (workspaces keep unsaved drafts), mutations never auto-retry                                                                 |
| Retry              | `shouldRetry`, `retryDelay`                    | network errors, 5xx and 429 retried at most twice (500 ms, 1 s backoff); 4xx (401/403/404/422) and aborts are final                                                                          |
| Dedupe and cache   | query keys in `queryKeys`                      | identical keys share one request; later mounts read the cache (selector → workspace reuses the account: 1 `/accounts/me/` request instead of 2)                                              |
| Cancellation       | `queryFn({ signal })`                          | unmounting the last observer aborts the in-flight request                                                                                                                                    |
| Invalidation       | `queryClient.invalidateQueries({ queryKey })`  | precise keys, e.g. `queryKeys.me`, `queryKeys.participantEvents(workspaceId)`                                                                                                                |
| Optimistic updates | `optimistic(client, key, apply)`               | applies to the cached value at once, restores the snapshot on error, revalidates on settle                                                                                                   |
| Session boundary   | `useSignOut`, `useSessionChanged`              | `resetQueries()` after sign-out and after sign-in: nothing cached for one account can be shown to the next                                                                                   |

Migrated now: the account (`useMe`: selector, workspace route, sign-out) and the participant events list (`TeamWorkspace`). The remaining raw `fetch` call sites are migrated together with the typed client (T03) and the workspace migration (T07); new code must use `useQuery`/`useMutation` over `apiRequest`, never `fetch` in an effect.

Evidence: `lib/api.test.ts` (request shape, error normalization, retry table), `hooks/useMe.test.tsx` (dedupe/cache, 401→signed-out without retry, 404 not retried, 503→503→200 retried, 3 attempts then error, invalidation refetch, abort on unmount, sign-out resets cache, optimistic apply/rollback/revalidate), `App.navigation.test.tsx` (one account request across selector and workspace), browser `server-state.spec.ts` (single `me` request; account switch in one SPA session shows nothing from the first account; 503 retried exactly twice then offered as Try again).
