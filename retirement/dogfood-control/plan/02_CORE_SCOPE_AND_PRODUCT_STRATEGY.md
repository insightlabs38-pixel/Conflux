# Core Scope and Product Strategy

## Core definition

Core is not synonymous with T1–T4. Core is the minimum adoption-quality product we intend to submit even if Stretch never begins.

### Core product capabilities above T4

1. Full multi-stage Stage DAG with branch/merge, stage-specific participation and advancement.
2. Typed Policy + Temporal Gate engine with scoped ExceptionGrants and human-readable decision evidence.
3. Versioned Forms, conditional fields, field visibility, typed Artifacts and rule-based Submission Preflight.
4. Durable Project identity distinct from stage evidence and immutable SubmissionVersions.
5. Normalization-aware judge assignment, regularized cross-judge normalization, fixture-backed Normalization Proof and judging-health diagnostics.
6. EvaluationPlan abstraction supporting multiple evaluation rounds/plans per stage.
7. Typed Awards/PrizePackages, eligibility/stacking/conflict rules and basic fulfillment.
8. Theme/Page/PageBlock public-site engine with polished defaults.
9. Event templates/cloning that copy configuration without participant data.
10. Canonical versioned import/export, API versioning, webhook schema versioning and migration/upgrade discipline.
11. Operations center, event launch checklist, segmented communications baseline, backup/restore smoke path.
12. Webhook signing/retries/replay, scoped API credentials, signed judge-participation records.
13. Duplicate/fraud/moderation evidence surfaces that preserve authoritative imported fixture records.

## Winning narratives

### Product narrative
A hackathon is not one submission form plus one judging page. Conflux models the complete event lifecycle as reusable stages, enforceable rules, evidence schemas, evaluations and awards.

### Judging narrative
Assignment is designed for comparability. Conflict constraints, coverage, expertise, load and overlap/connectivity feed into a normalization method that exposes raw → adjusted → final evidence rather than hiding the math.

### Adoption narrative
One command starts a seeded offline portal. Events can be exported/imported, upgraded, backed up, cloned and operated without a hosted dependency.

## Feature-addition rule

A new capability belongs only if it:
- eliminates organizer spreadsheet/email/manual work;
- reduces participant confusion/failure;
- materially improves judging integrity;
- improves portability/operability/adoption; or
- provides a clearly demonstrable competitive differentiator.
