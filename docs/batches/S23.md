# S23 — Optional GitHub/GitLab/Discord/Slack adapters

## Result
Complete. Submission CI evidence now covers public GitLab repositories the
same way it already covered GitHub, and outbound webhooks can deliver as a
native Discord or Slack chat message instead of only the signed Conflux
envelope -- both true "conveniences" (existing organizer-owned URLs/repos,
no new hosted service or OAuth app).

## Changes
- `artifacts.reachability.gitlab_evidence`/`GITLAB_REPO_PATH`: mirrors
  `github_evidence` exactly (best-effort license + latest-commit via
  GitLab's public REST API, never raises, never guesses). Wired into
  `inspect_submission_ci` alongside the existing `github.com` branch.
- `WebhookSubscription.platform` (generic/discord/slack, default generic,
  set at creation like `url`/`event_types`). `integrations.webhooks.
  chat_summary`/`payload_for`: a Discord/Slack subscription gets
  `{"content": ...}`/`{"text": ...}` built from the event type plus only
  the DomainEvent payload's scalar fields, through the exact same
  delivery/signing/retry pipeline every subscription already used.
  `WebhooksPanel` gets a delivery-format picker.

## Verification
- Backend: `pytest` full suite 609 passed/8 skipped; new tests in
  `test_artifact_reachability.py`/`test_artifact_ci_api.py` (GitLab
  evidence success/degrade/path-pattern, end-to-end CI check) and
  `test_webhook_chat_adapters.py` (summary formatting, per-platform
  payload shape, end-to-end Discord delivery).
- `ruff check`/`ruff format --check`, `makemigrations --check` (one
  migration for `platform`), `openapi`/SDK check: all clean.
- Frontend: `pnpm test` 79 passed (1 new), `tsc --noEmit`, `vite build`,
  `pnpm format:check`: clean except the pre-existing, out-of-scope
  `master/worker_prompt.md` finding.

## Limitations
- GitLab evidence only matches a flat `owner/repo` path, the same
  simplicity the existing GitHub check has; a nested GitLab subgroup path
  gets no evidence rather than a guess.
- No GitHub/GitLab adapter for the chat-message pattern exists because
  neither platform has an equivalent zero-auth "post JSON, get a message"
  incoming webhook; GitHub/GitLab conveniences land on the submission-CI
  side instead.
