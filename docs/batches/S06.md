# S06 — Blind judging/anonymization
## Result
Complete, scoped to what the product actually exposes: an organizer-set `EvaluationPlan.blind_judging` flag replaces a candidate's real project name with a deterministic pseudonym in a judge's own review queue.
## Changes
- `EvaluationPlan.blind_judging` (bool, default off), writable via the existing plan detail `PATCH`.
- `evaluations/anonymize.py::anonymized_label(plan_id, project_public_id)`: a stable SHA-256-derived label, same for every judge and stable across requests, with no persisted mapping to keep in sync.
- `CandidateListView` (JUX-001, the only judge-reachable endpoint that ever returned a project's real name) substitutes the pseudonym and orders by `public_id` instead of `name` under blind judging, so the queue order itself doesn't leak an alphabetical-by-identity signal.
## Verification
- New `tests/integration/test_blind_judging_api.py` (4): default real-name behavior, anonymization when enabled, label stability/uniqueness across projects and plans, and the organizer toggle round trip.
- Full suite: 495 passed, 8 skipped (was 491/8); `ruff format`/`check`, `manage.py check`, `makemigrations --check`, OpenAPI artifact check, `pnpm build`/`test` all clean.
## Limitations
- No institution/affiliation field exists on Project/Team to redact (none is modeled anywhere in the product) -- scope is project-name-as-identity only, the sole signal a judge is ever shown. Ballot/pairwise/calibration endpoints already never expose a project name at all, so they needed no change. Published results (`ResultsView`, technically judge-readable post-publish) are intentionally untouched: that's a distinct post-judging concern, not live-judging bias.
