# C-B29 — Concurrency/deadline correctness Core gate
## Result
Gate decision: **PASS with two findings fixed.** A real race (unlocked
team-size cap) and a real correctness bug (`select_for_update` +
`select_related` across a nullable FK, which PostgreSQL rejects outright).
No other unresolved P0/P1.
## Changes
- **Race (GCON-001):** `join_team`'s `MAX_TEAM_SIZE` cap was a plain
  `COUNT` with no row lock — confirmed with a real 3-thread race against
  PostgreSQL (all 3 succeeded, cap exceeded). Fixed: locks the `Team` row
  first.
- **Correctness:** `select_for_update()` chained with `select_related`
  across a nullable FK is a LEFT OUTER JOIN; PostgreSQL rejects `FOR
  UPDATE` there outright (SQLite silently allows it). Hit 4 real call
  sites (award winner selection, webhook staging/delivery, API credential
  revocation) that would crash in the deployed app. Fixed with
  `of=("self",)` everywhere this pattern appears, including 2 currently-
  safe sites (defensive; always correct).
- New `tests/integration/concurrency/`: real 2-3-thread races against
  PostgreSQL (team join, vote, ballot uniqueness); a static AST guard
  against a future call site omitting `of=("self",)` (no DB needed).
- **Verified (GCON-003):** no endpoint accepts a client-supplied timestamp
  for any deadline/gate check — every one uses the server clock.
## Verification
- Both bugs reproduced (confirmed failing), then fixed, then reproduced
  again (confirmed passing) against a disposable PostgreSQL 17 container,
  never this project's own compose stack.
- Full suite against real PostgreSQL → 435 passed, 4 skipped; against the
  SQLite default → 431 passed, 8 skipped. Ruff/Django check/migrations/
  OpenAPI clean.
## Limitations

  doesn't exist here) — targeted at the named mutation paths plus
