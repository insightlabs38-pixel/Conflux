# S21 — Feedback release controls

## Result
Complete. Organizers can now release judge ballot comments to a project's
own participants, gated exactly like results (never automatic, never on a
schedule) with an anonymity toggle.

## Changes
- `EvaluationPlan.feedback_visible_to_participants` (default False) and
  `feedback_anonymous` (default True): the same "explicit organizer
  opt-in" shape as `results_visible_to_participants`, patchable through
  the existing `EvaluationPlanDetailView` -- no new publish endpoint.
- New `GET .../evaluation-plans/<plan>/feedback/<project>/`: an
  organizer/admin may always read it; a participant only once the plan is
  released, and only for a project they belong to (404, not 403, for any
  other project -- matches `ProjectDetailView`'s existing pattern). Blank
  comments and calibration ballots are never shown.
- `EvaluationBuilder` gets the two toggles next to the existing results
  toggle.

## Verification
- Backend: `pytest` full suite 592 passed/8 skipped; new
  `tests/integration/test_feedback_release_api.py` (4 tests: gated until
  released, anonymous + project-scoped once released, identity opt-out,
  blank-comment omission).
- `ruff check`/`ruff format --check`, `makemigrations --check` (one
  migration for the two new fields), `openapi`/SDK check: all clean.
- Frontend: `pnpm test` 76 passed (1 new interaction test), `tsc --noEmit`,
  `vite build`, `pnpm format:check`: clean except the pre-existing,
  out-of-scope `master/worker_prompt.md` finding.

## Limitations
- No participant-facing "read my feedback" page was added -- the
  longer-standing, directly analogous `results_visible_to_participants`
  has never had one either, so this preserves an existing, apparently
  deliberate product boundary rather than inventing a new one unasked.
