# VS16 — Advanced team matching

## Result
Complete. Participant profiles and team openings gained roles, interests,
and weekly availability alongside skills; matching now ranks and explains
candidates/openings on all four signals, still fully opt-in and additive.

## Changes
- `MarketplaceProfile`/`TeamOpening` gain optional `roles`/`interests`
  (tag lists, same normalization as `skills`) and
  `availability_hours_per_week`/`min_availability_hours_per_week`
  (nullable). `marketplace.normalize_tags` generalizes the old
  skills-only validator.
- `matches_for_participant`/`matches_for_opening` now return
  `matched_roles`/`matched_interests`/`availability_compatible` (`None`
  when either side is unset) alongside `matched_skills`; deterministic
  rank: role overlap, then skill overlap, then interest overlap, then
  availability -- an availability shortfall never excludes a result, it
  only sorts after an otherwise-tied one.
- `MarketplacePanel.tsx`: profile/opening forms gain the three new inputs;
  match lists render a single `matchSummary()` line covering all signals.

  `test_advanced_matching_ranks_roles_over_skills_and_surfaces_availability`
  plus the 4 pre-existing marketplace tests, all passing.
- Frontend: `vitest run` 89 passed, `tsc --noEmit`, `vite build`: clean.

## Limitations
- Matching stays exact-tag/threshold based (no fuzzy skill/interest
  matching, no partial-availability scoring).
