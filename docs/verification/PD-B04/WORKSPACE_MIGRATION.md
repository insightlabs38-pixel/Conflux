# PD-B04-T07 — workspace migration onto the v3 foundations

Foundations now in place (T01-T06): nested routing, server-state layer (`useQuery`), typed transport (`lib/api.ts`), URL-state conventions, async-operation contract, realtime boundary. T07 moves the current workspaces onto them without changing backend semantics. The default for a panel that loads a resource on mount is `useLoad` (`hooks/useLoad.ts`): shared/deduped by URL, cancelled on unmount, revalidated on mount, `update()` applies a server-confirmed mutation result, `reload()` resolves when the fresh answer is in; no hand-written `useEffect` + request + `useState`.

`lib/serverState.test.ts` records every remaining effect-based fetch with its reason and fails on any new one; the ceiling only goes down (34 files with effect-based fetching before T07, 17 recorded now, 20 effects).

## Behavior preserved / deliberately changed

- Same endpoints, credentials, per-panel messages (`describe`), retry buttons and empty/loading/error states; no silent backoff retry (`useLoad` shows errors at once).
- Organizer/judge selections now survive refresh and links (T04); the old organizer flow (choose -> refresh) is a query key change.
- Mutation results update the cache (`update`) instead of local arrays; reads after writes use `reload()`.
- `OperationsCenter` renders the checklist and the summary independently (a failing summary no longer hides a loaded checklist).
- `JudgeInvitationInbox`/`JudgeDirectoryPanel` load failures now show a clean message instead of `ApiError: ...`.
