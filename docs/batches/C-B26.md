# C-B26 — Event templates, cloning and external qualifier
## Result
Complete. Organizers can save/reuse named event templates or clone an event
directly, choosing which config sections to include; a stage can now accept
externally-qualified results via API/webhook with identity continuity.
## Changes
- Canonical archive: two additive sections (`evaluation_plans`, `pages`)
  and an optional `sections` filter, dangling refs dropped/nulled not left
  broken (TPL-001/002, see docs/architecture/CANONICAL_ARCHIVE.md).
- `EventTemplate` + `integrations.templates`: save/instantiate a named
  config-mode archive, or clone an event directly in one call;
  `EventTemplatesPanel` (preview, section picks) in the event dashboard
  (TPL-003).
- `ExternalQualifierBinding`/`Import`: a stable `external_ref` → existing
  Project binding (never a new identity) entered into a team-based stage,
  idempotent on repeat calls, via session or API credential (EXTQ-001/002,
  docs/architecture/EXTERNAL_QUALIFIERS.md).
## Verification
- New tests → 21 passed; full backend suite → 418 passed, 3 skipped.
  Ruff/Django check/migrations/OpenAPI clean; `pnpm test`/`build` clean.
## Limitations
- External qualifier import supports team-based stages only (rejected
  explicitly for individual-mode stages, not silently guessed at).
