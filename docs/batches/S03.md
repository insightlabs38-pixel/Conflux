# S03 — Inter-rater agreement analytics
## Result
Complete. Organizers get an honest, live-computed view of judge disagreement: per-criterion score dispersion and per-judge-pair ranking correlation, with statistics backed by too little data reported as absent rather than fabricated.
## Changes
- `evaluations/agreement.py`: `criterion_disagreement` (per project/criterion, only where ≥2 judges scored it — mean/range/population-stdev) and `pairwise_rank_agreement` (Kendall's tau-b between every judge pair's own weighted-score-induced ranking, `tau=None` below a 3-shared-candidate floor since a 2-point correlation is always exactly ±1 or 0 and means nothing). No new model — always computed live, never frozen as a "run" (this is a diagnostic, not published evidence).
- New organizer-only, rubric-mode-only `GET .../evaluation-plans/<id>/agreement/`.
## Verification
- New `tests/integration/test_agreement_estimator.py` (8, pure math) and `tests/integration/test_agreement_api.py` (4, API): dispersion computation/sorting/absence-below-threshold, tau for identical/reversed/degenerate rankings, organizer-only access, and pairwise-mode rejection.
- Full suite: 480 passed, 8 skipped (was 468/8); `ruff format`/`check`, `manage.py check`, `makemigrations --check` (no migration needed), OpenAPI artifact check, `pnpm build`/`test` all clean.
## Limitations
- Ranking correlation ranks by the plan's live weighted score, not a formal partial/weighted-Kendall variant; ties are handled (tau-b) but not modeled per-criterion.
- No organizer frontend yet (API-only, same as S01/S02).
