## Cross-cutting checks

- Authorization and visibility: no server change in this slice. Every pane and list reads endpoints that already authorize; the operations pane offers organizer-only panels to organizers and admins only; selection and tab commands only start existing workflows (the bulk move still opens its previewed, receipted planner).
- Migration and compatibility: no model, API, SDK or archive contract changed. Device-local keys are new and versioned (`conflux:v1:`): `columns:<entity>`, `tabs`, `ops-pane`, `live-operations`; legacy URLs still redirect, and the new `sort_`/`page_` params are ignored by older links. Drafts are memory only and discarded at sign-out.
- States and viewports: every new surface is tested at desktop and the 390 mobile project with axe where it renders; the operations pane at 1920 and absent at 1440; loading, empty, error, offline and degraded states are in component or browser tests.
- Regressions found and fixed during this verification: the first share-link allowlist kept any safe-looking key (typed text could leak) and was replaced by an explicit key list; the new account-menu control as a checkbox broke two existing tests that look for the first non-radio input, so it is a radio group like theme and density; hooks added to `AppShell`'s own body broke public shells that have no query client, so they moved to a child that only workspace shells render; four palette-driven browser specs raced the option list and now wait for the option; a unit test matched header text that varies with timing and now strips the sort hint; the visual ratchets rejected three raw sizes and radii in new CSS, now scale tokens.
