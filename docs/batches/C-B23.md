# C-B23 — Certificates, signed judge records and embed
## Result
Complete. Organizers can issue signed event/project/judge records that anyone can verify offline, and the public gallery is embeddable on any external page via a dependency-light Web Component.
## Changes
- `presentation.records`/`keys` (REC-001/002): Ed25519-signed JWT records (`event`/`project`/`judge` kinds), every claim read from real event data — no fixed template. Key is derived deterministically from `RECORD_SIGNING_KEY_SEED` (new required env var, wired through Makefile/.env.example/docker-compose.yml), so it survives restarts with no persisted key material.
- New routes: organizer-only issuance (`.../records/{event,project,judge}/`), public `GET records/verification-key/` and `POST records/verify/` (REC-003) — the same check anyone can run themselves, offline, with the published key.
- `/e/verify/` (REC-003): a plain server-rendered page over the same check, `?token=` shareable.
- `GET /api/v1/events/<event>/gallery/` (new, additive JSON API next to the existing HTML gallery — see X011) backs `<conflux-gallery>`, a zero-runtime-dependency Web Component in `src/embed` (EMB-001), built with esbuild to a single ~2KB file. `docs/embed/README.md` + `examples/embed.html` (EMB-002) cover self-hosted/offline usage.
- Added `cryptography`/`pyjwt` as explicit dependencies (`pyjwt` was previously only transitive).
## Verification
- `pytest -q tests/integration/test_verifiable_records.py tests/integration/test_records_api.py` → 13 passed, incl. tamper-detection and a non-judge rejection.
- Full backend suite → 393 passed, 3 skipped. Ruff, Django check, makemigrations --check, OpenAPI artifact check → all clean.
- `pnpm --filter @conflux/embed test` → 7 passed (incl. an XSS-escaping test for untrusted gallery fields). `pnpm build`/`pnpm lint`/`pnpm test` now cover both `@conflux/web` and `@conflux/embed`.
## Limitations
- No key rotation/multi-key support; records are stateless (no revocation) — see docs/architecture/VERIFIABLE_RECORDS.md.
- `pnpm format:check` (prettier) already fails on `base.html`/`gallery.html` before this batch (Django template tags inside HTML attributes aren't valid HTML to its parser) — pre-existing, unrelated to this batch, not touched.
