# S19 — Public static archive

## Result
Complete. The public event/gallery/project pages and JSON API no longer
disappear when an event closes or is archived, and the page-builder
"results" block now renders real published award winners instead of a
static placeholder.

## Changes
- `events.models.PUBLICLY_VISIBLE_STATUSES` (open/closed/archived; draft
  stays hidden) replaces the `status=OPEN`-only gate in both public entry
  points: `events.views.PublicEventView` and
  `presentation.public.get_public_event`. Finalized submissions and
  archived events are already immutable, so the archive is stable by
  construction once it's reachable.
- `awards.services.published_awards_for_public_display`: a narrow public
  shape (award name + winning project names only, no selection mechanics)
  reused by the page builder; `PublicAwardsView`'s own shape is untouched.
- `presentation.site_views._blocks_with_live_data` now wires the existing
  `PageBlockKind.RESULTS` block to that data; `event_landing.html` renders
  it as a project list per award, falling back to the original placeholder
  when nothing is published yet.

## Verification
- Backend: `pytest` full suite 583 passed/8 skipped; new
  `tests/integration/test_public_archive.py` (5 tests: post-close/archive
  reachability, draft stays hidden, results block rendering, unpublished
  award omission) plus 1 new case in `test_public_event.py`.
- `ruff check`/`ruff format --check`, `makemigrations --check` (no model
  changes), `openapi` check: all clean (no API response shape changed, so
  the committed schema/SDKs needed no regeneration).

## Limitations
- The results block only appears where an organizer has actually placed
  one on their page (existing page-builder behavior, unchanged).
