# S01 — Pairwise judging + Bradley–Terry
## Result
Complete. An `EvaluationPlan` can now run in `pairwise` mode: judges compare two candidates head-to-head instead of scoring a rubric, and results are ranked by an immutable, deterministic Bradley-Terry strength run.
## Changes
- `evaluations/pairwise.py`: a regularized Bradley-Terry MM estimator (`estimate_strengths`), a `PairwiseComparison` → `(winner, loser, weight)` bridge, and `run()` freezing an immutable `PairwiseRun` — the pairwise analogue of `normalization.py`.
- New models `PairwiseComparison` (canonical `project_a_id < project_b_id` storage, tie = null winner) and `PairwiseRun`; `EvaluationPlan.mode` (`rubric`/`pairwise`, default `rubric`) and `published_pairwise_run`.
- New, fully additive API surface under `.../evaluation-plans/<id>/pairwise/`: `next/` (coverage-balancing next-pair picker, shared `_eligible_candidates` helper with the rubric queue), `comparisons/`, `runs/`, `publish-results/`, `results/`, `results.csv` — parallel to the rubric endpoints, not merged into them, so `awards`' existing `ranked_results`/`published_normalization_run` coupling is untouched.
- Mode guards: a `pairwise`-mode plan rejects rubric ballot/normalization-run writes and vice versa, so the two evidence tables never mix for one plan.
- `JUDGING.md` documents the method, queue strategy and the one known limitation.
## Verification
- New `tests/integration/test_pairwise_estimator.py` (7) and `tests/integration/test_pairwise_judging_api.py` (11): convergence/determinism/tie/regularization math, canonical ordering, duplicate/self/conflict rejection, isolation, mode cross-rejection, next-pair coverage balancing and exhaustion, and a full compute→publish→read→CSV round trip.
- Full suite: 459 passed, 8 skipped (was 441/8); `ruff format`/`check`, `manage.py check`, `makemigrations --check`, OpenAPI artifact check, `pnpm build`/`test` (65 web + 7 embed) all clean.
## Limitations
- No organizer/judge frontend for pairwise mode yet (API-only); award winner selection doesn't read `published_pairwise_run` yet (documented in JUDGING.md).
- Next-pair balancing is a simple min-load greedy scan (fine at hackathon scale), not an active-sampling algorithm.
