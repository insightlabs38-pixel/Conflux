## State and viewport coverage

- Normal, loading, error and refused states of the preview: `LoadingState` while the first page is drawn, `ErrorState` with kept and retry text for a refused draft or a failed request (`PagePreview.test.tsx`, e2e).
- Empty: an event with no page yet previews the default and creates nothing (`test_page_preview.py`); a page with no hero or lead shows the default hero.
- Mobile: header, hero band, project page and immersive art each have a measured cap at 390; touch targets stay 44px (B01).
- Public pages keep `public`, `showcase`, `foundations`, `event-themes` green with axe at 390 and 1440.

## Authorization, lifecycle, concurrency, migration

- Authorization: every mutation is the existing organizer-only page and block API; the new preview surface is organizer and admin only and read-only. Participant and judge are refused, another workspace's event is not found.
- Lifecycle and concurrency: no new state or lifecycle. Adding a lead shifts block positions inside one transaction.
- Migration and compatibility: `presentation 0006` changes the allowed values of `PageBlock.kind` only (no data change); absent theme keys keep their old meaning; stored unsafe block links render as no link. OpenAPI and SDKs regenerated and checked.

## Defects found by this batch's verification (fixed in the product, nothing relaxed)

- Organizer-typed block links were rendered unchecked on an origin shared with the application (stored `javascript:` link); fixed at save time and at render time (T05).
- Server-rendered public templates still emitted the removed `cx-badge` class; statuses were bare text (fixed with a ratchet and a check on the gallery and project page).
- The public header took 180px on a phone (T04).
