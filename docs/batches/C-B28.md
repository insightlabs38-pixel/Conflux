# C-B28 — Security/adversarial Core gate
## Result
Gate decision: **PASS with one finding fixed.** Reviewed authorization
architecture and high-risk endpoints; found and fixed one real P1 (stored
XSS via non-image/video artifact uploads); no other unresolved P0/P1.
## Changes
- **Found (GSEC-001/002):** the object store is served same-origin with
  the app (infra/Caddyfile); `file`/`document`/`dataset`-kind uploads had
  no content-type check, and `image`-kind accepted `image/svg+xml` (passes
  a naive `image/*` check but can embed `<script>`) — a malicious public
  upload could execute script in the app's own origin.
- **Fixed:** `presign_get` now always forces `Content-Disposition:
  attachment`; validation rejects `text/html`/`application/xhtml+xml`/
  `image/svg+xml` for every kind, not just image/video. See
  docs/architecture/ARTIFACT_SERVING.md, DECISIONS.md X014.
- **Reviewed, no issue found:** RBAC/IDOR scoping, judge ballot isolation,
  webhook SSRF/signing (DNS-rebinding-proof), object-key generation
  (server-only UUIDs), role-grant authorization, invite replay,
  community-vote uniqueness/rate limiting, cache leakage (no app cache
  backend exists at all).
- `SECURITY.md` finalized with the threat model and per-threat evidence
  (GSEC-003).
## Verification
- New tests → 6 passed; full suite → 430 passed, 4 skipped.
  Ruff/Django check/migrations/OpenAPI clean. No frontend files touched.
## Limitations
- No live fuzz/permutation matrix run (Freebuff owned that breadth; it
  doesn't exist here) — a targeted architectural review, not exhaustive
  brute-force coverage.
