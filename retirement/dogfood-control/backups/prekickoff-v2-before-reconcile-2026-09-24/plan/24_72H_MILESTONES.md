# 72-Hour Milestones

These are control points, not rigid feature clocks. High-throughput implementation may move work earlier; gates prevent breadth from degrading correctness.

## H0–H4 — legal bootstrap + foundations
Create repo only after kickoff; BOOT-B00; runtime/auth/application spine; fixture importer; acceptance first green target.

## H4–H16 — T1 + workflow primitives
Permanent T1 green; event/stage/policy/teams/project/forms/artifacts/submission work begins in parallel.

## H12–H26 — T2/judging spine
Evaluation/rubric/judge assignment, peer-score isolation, CSV, judge UX; normalization work starts once score model is stable.

## H20–H36 — T3/T4 + Core differentiators
Community, API/webhooks, canonical archive, signed records/embed, awards/operations/templates. Keep T1/T2 green.

## H28–H46 — judging hero + Core depth
Normalization-aware assignment/proof, polished builders, launch/preflight/operations/compatibility.

## H36–H56 — Core completion + promoted Stretch
Pairwise and other Stretch can run if release gates remain healthy. Continuous Freebuff fuzz/property/security/e2e campaigns trail merged implementation.

## H52–H64 — hardening and adoption
Security/concurrency/judging/performance gates, offline cold boot, backup/restore, migrations, import/export, accessibility/product consistency.

## H60–H68 — release compression
No speculative architecture. Stretch/Very Stretch only low-risk isolated work. Fix P0/P1, run full verify, docs and demo rehearsal.

## H68–H72 — release freeze
Release candidate only: official acceptance report, final docs, demo video, submission metadata. Claude handles only critical blockers; Freebuff runs regression/polish; no risky expansion.
