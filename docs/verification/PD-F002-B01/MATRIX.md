## Cross-cutting proofs (`test_shared_primitives_b01_regression.py`)

- `test_core_depends_on_no_domain_app`: no module of `core` imports a domain app (ESC-20260930-004).
- `test_the_registries_hold_exactly_what_production_registers`: bulk actions, job kinds, approval policies, thread subjects, timeline providers and entities are exactly the intended set (guards against test pollution and accidental removal).
- `test_the_primitive_registry_marks_the_eight_owners_implemented`: `PRIMITIVE_REGISTRY.yaml` agrees with the code.
- `test_every_route_refuses_signed_out_callers_and_people_outside_the_workspace` and `test_organizer_only_routes_refuse_a_participant_and_nothing_is_leaked`: 14 routes across the eight primitives.
- `test_every_mutating_primitive_leaves_an_audit_record`: saved view, job, gate, approval request and decision, thread comment and bulk apply each audit; comment text never reaches the audit.
- `test_an_archived_event_refuses_what_the_primitives_would_change`: gates, thread writes and bulk refuse; reading, the timeline and an archive export job still work.

## Unresolved limitations (carried to the batch receipt)

Saved column widths, inline editing and the other nine hand-written tables (T03); compensation after a bulk apply is not generic and there is no bulk history screen (T04); job artifacts live in the database, no retention sweep or retry (T05); deciders are not notified and the browser fixture has one organizer so the second person's approval is proved in integration only (T06); no note counts in grids, no people picker, `public` audience is for members (T07); no participant or public timeline, no calendar grid (T08).
