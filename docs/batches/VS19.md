# VS19 — Sponsor portal

## Result
Sponsors tagged on an award can now see its prize definition, eligible
projects, assigned judges, and winners, and advance its fulfillments
through the exact same state machine organizers use -- scoped to only
the awards they're tagged on.

## Changes
- `Award.sponsor_contacts` (M2M to User, organizer-managed via
  `PUT/DELETE .../awards/<id>/sponsors/<user>/`, requires the target hold
  Role.SPONSOR). Never exposed on the public unauthenticated awards feed
  (stripped from `PublicAwardsView`'s payload).
- `awards.sponsor_portal`: `GET sponsor-portal/awards/` (sponsor sees only
  tagged awards; organizer/admin see all) adds `eligible_projects`
  (award's track/finalized-submission rules applied to `Project`) and
  `judges` (the award's evaluation plan's pool members, if any) on top of
  the existing organizer `award_data` shape -- one source of truth, no
  parallel read path to drift from the organizer view.
- `PATCH sponsor-portal/fulfillments/<id>/` reuses `services.
  advance_fulfillment` unchanged (same transition rules, same failure-
  needs-a-note check); only a sponsor-contact of that award, or an
  organizer/admin, may call it.
- Promoted `awards.views._award_data`/`_fulfillment_data` to
  `award_data`/`fulfillment_data` (module-private helpers used only
  within `views.py` stay private) since the sponsor portal now shares
  them across modules.

## Verification

  `test_sponsor_portal.py` (3 tests: scoped visibility + judges/eligible-
  projects shape, fulfillment advancement restricted to the tagged
  sponsor, access revoked after removing the sponsor tag). Existing
  `test_award_api.py`/`test_award_models.py`/`test_award_selection.py`/
  `test_award_solver.py` (20 tests) still pass unchanged.
- `ruff format/check`, `makemigrations --check` (new
  `awards.0004_award_sponsor_contacts`), `manage.py check`, OpenAPI/SDK
  check, SDK `tsc` build: all clean.
- Repo-wide `pnpm format:check` still only fails on the pre-existing,
  untracked `master/` scaffolding from the abandoned orchestration
  campaign, unrelated and left untouched.

## Limitations
- API/SDK-only: no sponsor-facing frontend page exists yet (VS18 also
  shipped its roles API-only for the same reason -- there is no
  self-serve UI surface for any of these new roles to sign into). The
  organizer-side `AwardsPanel.tsx` also has no UI yet for tagging a
  sponsor contact; that's a `PUT`/`DELETE` call away for a future batch.
