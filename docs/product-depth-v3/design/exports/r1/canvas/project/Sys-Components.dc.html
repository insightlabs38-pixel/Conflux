Component grammar

Rules first, pixels second. Every organizer page is assembled from this list; anything not here needs a documented escalation.

Buttons & actions

One primary per local context
  • Primary (filled accent): the single forward action of a panel/page. Right-aligned in footers, left of the toolbar cluster in headers.
  • Secondary (outlined): default. Ghost: cancel, tertiary, toolbar tools. Icon-only needs aria-label + tooltip.
  • Frequent actions stay visible. Kebab menus hold ≤4 rare actions; a row exposes 1–2 inline actions on hover/focus (.rowact) and the same actions in the inspector.
  • Destructive = outlined neutral → confirmation dialog whose final button is the only red element. Label states the object and count: “Remove 12 participants”.
  • Disabled buttons explain why in an adjacent hint or tooltip reachable by keyboard.
  • Async: button shows spinner + present-tense verb, stays same width, blocks double-submit; result goes to inline status or toast (undo where reversible).

  • Header: 32px, sticky, sentence case, sort glyph only on sortable columns; sorted column ink + accent glyph.
  • Alignment: text left, numbers right in tabular figures, status left. IDs mono, tertiary.
  • States: hover = 2% wash · selected = accent tint (+ checked box) · cursor = 2px accent left edge + top/bottom rule (keyboard). Selected ≠ cursor.

  • Inspector (non-modal, right, 380–480, resizable): the default way to view/edit a row. Esc closes, focus returns to the row. Never covers the table it inspects at ≥1280.
  • Dialog (modal, ≤480, centred): irreversible or plan/approve steps only. Title = verb + object; body states scope and reversibility; focus starts on Cancel for destructive.

Motion · focus · keyboard

JK↑↓Space⇧ Click⌘ K?
  • Focus ring: 2px accent outline with 2px surface gap, on every interactive element; never removed. Visible on tinted rows and in forced-colors.
  • Motion: 120–180ms opacity/transform for inspector, popover, toast only. No ambient, parallax or looping decoration; spinners/skeletons stop under prefers-reduced-motion (static state text remains).
  • Global keys: ⌘K command/search · ? shortcuts · G then letter navigates · / focus search · Esc close top layer. Grid: J/K or arrows move cursor, X/Space select, ⇧+arrows range, ↵ open inspector, E edit cell.
  • Tab order follows visual order; inspector is inserted after its list; dialogs trap focus and restore it. Grids are a role=grid with one tab stop and roving focus.

Anti-slop rules — review gate for every screen

A PR that violates one needs a written exception
No gradients in chrome, buttons or backgrounds (data-viz ramps and placeholder art excepted).
No coloured icon tiles next to headings; icons are 16px, currentColor.
No KPI-card grids — use a summary strip (one hairline, ≤6 figures) linked to filtered records.
No nested cards — one panel level; use hairlines and headings inside.
No pill soup — ≤1 tag per row; attributes are text or columns.
No oversized titles in the app; no marketing copy in operator screens.
No repeated labels in breadcrumb + H1 + card title.
No hidden primary actions in kebab menus.
No alarm pages — red only on the failing item and final destructive button.
No fake “AI” affordances on deterministic flows (scores, eligibility, winners).
No false precision — 2 decimals max; dates in event timezone with relative hint.
No opaque IDs as input — pickers show names; IDs are copyable secondary text.
No glass / blur / ambient motion. Shadow only on floating layers.
No 3-column card dashboards where a sortable table is the task.
Screenshot test: crop any region — it must read as mature production software with no context.
