# VS03 — Rubric + pairwise hybrid evaluation

## Result
Complete. A rubric plan's close calls (adjacent-rank candidates whose
scores are too near to confidently order) can now be resolved by a
linked pairwise "tie-break" plan whose eligible candidates are
structurally bounded to exactly that close-call set.

## Changes
- `evaluations.hybrid.close_call_project_ids(source_plan,
  normalization_run, margin_fraction=0.05)`: pure function over an
  already-published `ranked_results`, never invents evidence. A flat
  score range (every candidate tied) treats every adjacent pair as close.
- `EvaluationPlan.hybrid_source` (nullable self-FK): only settable on a
  PAIRWISE plan, pointing at a RUBRIC plan on the same stage (`clean()`
  enforces both, plus rejects self-reference). `eligibility.
  eligible_projects` bounds a hybrid plan's candidates to its source's
  latest normalization run's close calls -- empty (not "everything") if
  no run has been published yet. This is the same eligibility check
  every comparison submission already runs, so a judge cannot submit a
  comparison outside the bound; no separate validation layer was added.
- New organizer-only `GET .../close-calls/` (rubric-mode plans only):
  preview of the current bounded set before deciding whether a tie-break
  round is worth setting up.

## Verification
- Backend: `pytest` full suite 640 passed/8 skipped; new
  `tests/integration/test_hybrid_evaluation.py` (7 tests: close-call
  clustering excludes a real outlier, the endpoint reports the same set,
  empty-before-any-run, bounded eligibility allows an in-cluster pair and
  rejects an out-of-cluster one even for a real finalized candidate,
  unbounded-before-any-run, all four `clean()` rejections, permission).
- `ruff check`/`ruff format --check`, `makemigrations --check` (one
  migration for `hybrid_source`), `openapi`/SDK check: all clean.
- No frontend UI was added: assignment preview/activate/rebalance and
  pairwise comparisons have never had one either (API/SDK-only), the same
  boundary VS01/VS02 already documented.

## Limitations
- `margin_fraction` (0.05) is a fixed default, not yet organizer-tunable
  through the API (callers of the pure function can already override it).
- **Process note, not a functional issue:** a `ruff format src/api tests`
  invocation during this batch's cleanup swept up
  `tests/test_master_supervisor.py`, the owner's own file that earlier
  batches' `CURRENT_STATE.md` note says is "not this worker's to touch."
  The change is formatting-only (ruff format never alters semantics; the
  file's syntax and behavior are unchanged), and there is no prior git
  baseline to diff against since the file was never tracked -- so it
  cannot be precisely reverted. Every `ruff format`/`ruff check --fix`
  call for the rest of this session names exact file paths, never a bare
  directory, to prevent a repeat.
