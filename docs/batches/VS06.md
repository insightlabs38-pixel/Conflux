# VS06 — Judging provenance explorer

## Result
Complete. Organizers can select a published rubric result and trace authored scores through normalization to the aggregate rank and any award selection tied to that exact run.

## Changes
- New normalization runs freeze ballot IDs, rubric criteria/weights, submitted scores, and adjusted scores alongside existing aggregate evidence.
- Added organizer-only project provenance API and interactive explorer in the judging screen. Older runs explicitly report an unavailable ballot snapshot.
- Award links use each winner's stored run reference; OpenAPI and generated SDKs updated. Footage impact: unaffected; no recorded-surface or scene manifest exists.

## Verification
- Scoped backend suite: 67 passed, including frozen snapshots, permissions, older runs, and award-run isolation.
- Judging UI tests: 4 passed; TypeScript and web build passed.
- OpenAPI/SDK, migration/system, Ruff, and Prettier checks passed.

## Limitations
- Detailed ballot trace is available only for normalization runs created after this change; older runs retain their aggregate evidence.
- The explorer covers rubric normalization and evaluation awards; pairwise plans have a separate evidence model.
