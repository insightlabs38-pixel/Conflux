# VS04 — Ranking sensitivity explorer

## Result
Complete. Organizers can compare current rubric-ballot rankings with alternate judge-bias strengths, single-judge removal, and earlier submission prefixes.

## Changes
- Added a read-only `POST .../sensitivity/` endpoint with public project IDs and judge usernames; it never creates normalization runs.
- Uses each ballot's frozen rubric weights and deterministic submission order. Invalid or non-finite inputs fail validation.
- Published the endpoint in OpenAPI and generated TypeScript/Python SDKs.

## Verification
- Scoped evaluation suite: 67 passed; focused sensitivity suite after final validation change: 14 passed.
- OpenAPI and SDK checks, migration check, Ruff lint/format: passed.

## Limitations
- Incompleteness scenarios remove the most recent submitted ballots; they are a deterministic historical proxy, not a prediction of future ballots.
- This batch adds API/SDK access without an organizer UI.
