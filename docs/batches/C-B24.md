# C-B24 — Awards, typed prizes and fulfillment
## Result
Complete. Event awards are independent from evaluations and support winner publication and prize fulfillment.
## Changes
- Modeled eligibility, source, capacity, stacking, conflicts, typed components, winners, and fulfillment.
- Added audited organizer selection with explicit source override evidence and public winner publication.
- Added organizer and public UI surfaces without changing the existing event layout.
- Fixed the organizer candidate picker: it was wired to the caller-membership-
  scoped project list, so organizers would miss most candidates. Added an
  event-scoped `candidates/` endpoint (`AwardCandidateView`) and repointed
  `AwardsPanel` to it.
## Verification
- `pytest -q tests/integration/test_award_api.py tests/integration/test_award_models.py tests/integration/test_award_selection.py` → 10 passed (incl. new regression test proving candidates aren't limited to the caller's own projects).
- Full backend suite (`pytest -q -n auto`) → 367 passed, 3 skipped.
- Ruff, Django check, makemigrations --check, OpenAPI artifact check → all clean.
- Frontend `pnpm test` → 44 passed. `pnpm build` → clean.
## Limitations
- Evaluation plan entry uses a public ID; failed/claimed fulfillment is terminal.
- No dedicated frontend test for `AwardsPanel`; organizer-facing behavior is covered via the backend API contract test.
