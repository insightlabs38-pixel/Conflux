# C-B31 — Performance and reliability Core gate
## Result
Gate decision: **PASS for the documented disposable profile.** Five real HTTP scenarios completed without status errors; a worker outage and app restart preserved authoritative records.
## Changes
- Added a k6 runner with explicit per-scenario requests, concurrency, expected statuses, and duplicate-write protection.
- Fixed seven judging mutations so audit rows and domain writes share a request transaction. The live ballot 500 was reproduced before the fix and cleared after it.
- Recorded hardware, seed size, concurrency, request counts, and measured latency in `loadtests/results/C-B31.json`.
## Verification
- Isolated PostgreSQL/Valkey/RustFS stack: 100 baseline reads, 40 deadline writes, 20 ballots, 20 votes, 200 gallery reads; all expected statuses, zero HTTP failures. p95: 105/146/200/108/139 ms respectively.
- Worker stopped: vote 201. After app/worker restart: 21 votes, 20 ballots, 80 finalized submissions persisted; gallery 200 with 80 projects.
- Full pytest suite: 443 passed, 8 skipped; affected Ruff checks and format checks passed.
## Limitations
- Short runs on a single VM, direct to the app port; these are scoped engineering measurements, not sustained-load or production HA claims. Public gallery was uncached, so its 139 ms p95 does not establish the provisional cached-read budget.
