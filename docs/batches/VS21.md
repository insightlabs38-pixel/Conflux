# VS21 — Offline judge PWA

## Result
A judge's assigned projects and published rubric are cached on every
successful load; a ballot that fails to submit because the request never
reached the server (not because the server rejected it) queues locally
and replays automatically once the browser reports connectivity again.

## Changes
- `JudgeWorkspace.tsx` (`PlanQueue`): on a successful `candidates/` +
  `publish-rubric/` load, writes both to `localStorage`
  (`conflux.judge-cache.<plan>`); on a failed load that looks like a
  genuine network failure (`TypeError` from `fetch`, or
  `!navigator.onLine`) with a cache present, falls back to it and shows an
  "You're offline" banner instead of erroring.
- `BallotForm.submit()`: a network-failure ballot POST queues the payload
  (`conflux.judge-outbox.<plan>`, one entry per project, latest wins) and
  the candidate renders as a distinct "queued" status (locked inputs, its
  own status line) rather than an error -- a genuine server rejection
  (validation error, already-submitted) still surfaces as a normal error
  and is never queued. The draft-autosave PUT is best-effort during
  submit: a network failure there is swallowed since the ballot POST
  carries the same responses/comment anyway.
- Reconciliation: a `window "online"` listener re-triggers the load, which
  replays the outbox in order, stopping at the first still-offline
  failure but dropping an entry the server actually rejects (nothing
  further retry can do); a queue banner shows the pending count.

## Verification
- Frontend: `vitest run` 92 passed (new `JudgeWorkspace.offline.test.tsx`,
  2 tests: queue-while-offline-then-sync-on-`online`-event end to end, and
  cached assignments/rubric rendering on a simulated reopen while
  offline), `tsc --noEmit`, `vite build`: clean. Existing
  `JudgeWorkspace.navigation.test.tsx`'s offline-adjacent 503 case
  (server rejection, not a network failure) still behaves unchanged.
- No backend files changed -- this is entirely a frontend capability
  layered on the existing `ballots/`/`candidates/`/`publish-rubric/`
  endpoints, so the backend suite is unaffected by construction.
- `pnpm format:check`/lint on the touched files: clean (repo-wide
  `pnpm format:check` still only fails on the pre-existing, untracked
  `master/` scaffolding from the abandoned orchestration campaign,
  unrelated and left untouched).

## Limitations
- Not a true installable PWA (no manifest/service worker) -- "offline"
  here means "the tab is already open and `localStorage` has yesterday's
  data," not "launch the app with zero network at all." A full add-to-
  home-screen PWA is VS22's job (installable event/public PWA), the next
  batch in sequence.
- Draft autosave itself isn't queued offline (only the final ballot
  submission is); a network failure there degrades to the existing manual
  "Retry draft save" button.
- The outbox is per-browser `localStorage`, not synced across devices.
