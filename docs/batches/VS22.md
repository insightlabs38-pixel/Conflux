# VS22 — Installable event/public PWA

## Result
The public event site is installable (manifest + icon) and gains a new
live "Announcements" block alongside the existing agenda (schedule) and
projects (gallery) content; a service worker gives it an optional offline
shell for previously-visited pages.

## Changes
- `events.Announcement` (event/title/body/posted_by/created_at, organizer
  CRUD at `announcements/`), rendered on the public site through a new
  `PageBlockKind.ANNOUNCEMENTS` live block -- same "always real data, never
  stale organizer content" treatment as `schedule`/`gallery`/`results`.
  Added to `PageBuilder.tsx`'s kind picker so organizers can actually add
  it.
- `manifest.webmanifest` + `icon.svg` (static, served under `/static/`),
  linked from `presentation/base.html` along with a `theme-color` meta;
  `start_url`/`scope` are deliberately omitted so each event page defaults
  to being its own install/launch point (per spec, unset `start_url`
  defaults to the referring document).
- `sw.js` served under `/e/sw.js` (not `/static/`) specifically so its
  default scope covers every event page -- a service worker can't control
  paths outside the directory it's served from without a
  `Service-Worker-Allowed` header, which plain static serving doesn't set
  here. Network-first for `/e/*` pages (falls back to the last cached
  response offline), cache-first for the shell's own assets. Registration
  in `base.html` is best-effort (`.catch(() => {})`): the site works fully
  without it.

## Verification
- Backend: `pytest` full suite 719 passed/8 skipped; new
  `test_announcements.py` (3 tests: organizer-only CRUD, the live block
  rendering real announcement content plus the manifest link on the
  public page, and the service worker being served with the right
  content-type from the site path).
- Frontend: `vitest run` 92 passed, `tsc --noEmit`, `vite build`: clean.
- `ruff format/check`, `makemigrations --check` (new
  `events.0004_announcement`, `presentation.0002_alter_pageblock_kind`),
  `manage.py check`, OpenAPI/SDK check: all clean.
- Manually confirmed `django.contrib.staticfiles.finders.find(...)`
  resolves `sw.js`/`manifest.webmanifest`/`icon.svg` from
  `STATICFILES_DIRS`.
- Repo-wide `pnpm format:check` still only fails on the pre-existing,
  untracked `master/` scaffolding from the abandoned orchestration
  campaign, unrelated and left untouched.

## Limitations
- No offline queueing of organizer actions -- this batch is read-only
  offline support for the public site, distinct from VS21's judge-side
  ballot queue.
- The manifest icon is a single flat SVG, not a maskable-safe-zone PNG
  icon set; acceptable for "installable" but not a polished app icon.
- Cache versioning is a single hardcoded `CACHE` name (`conflux-shell-v1`)
  bumped by hand on future shell-asset changes, not content-hashed.
