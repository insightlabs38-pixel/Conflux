# S24 — Judge schedule/workload calendar

## Result
Complete. A judge can now see their own time-aware view across an entire
event (open/closed windows plus per-plan assigned/submitted progress) in
one place, and an organizer can see every judge's completion roll-up
sorted least-complete first.

## Changes
- New organizer/judge `GET .../judge-calendar/`: the event's
  `TemporalGate`s (not tied to a specific plan in the data model, so
  reported alongside assignments rather than an invented per-plan link)
  plus, for the requesting judge, one entry per plan they actually have
  eligible candidates in -- reuses `_eligible_candidates` so eligibility
  (pool strategy, conflicts, prize-pool membership) matches judging
  itself exactly, never re-derived.
- New organizer-only `GET .../judge-workload/`: the same per-judge
  assigned/submitted counts, rolled up across the whole workspace judge
  roster and every plan, sorted least-complete first; counts only, never
  ballot content.
- `JudgeCalendarPanel` on `JudgeWorkspace` and `JudgeWorkloadPanel` on the
  organizer event dashboard.

## Verification

- `ruff check`/`ruff format --check`, `makemigrations --check` (no model

## Limitations
- None found beyond what's already inherent to `TemporalGate` not being
  scoped to a specific plan/stage in the existing data model.
