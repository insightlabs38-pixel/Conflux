# S20 — Multi-round workflow presets

## Result
Complete. An organizer can bootstrap a fresh event's screening/semifinal/
final stage graph and one evaluation plan per round in a single action,
instead of wiring each stage/transition/plan by hand.

## Changes
- `evaluations.workflow_presets`: two named presets (`two_round`:
  Screening → Final, `three_round`: Screening → Semifinal → Final), the
  same "form control instead of hand-wiring" shape as `policies.presets`.
  Builds an ordinary Stage/StageTransition chain plus one draft
  EvaluationPlan per stage through the existing models; later rounds
  default to `TEAM_LOCKED` participation. Refuses (never merges) if the
  event already has any stage.
- New organizer-only `GET .../workflow-presets/` (list) and
  `POST .../workflow-presets/apply/` (create), reusing `StageSerializer`/
  `EvaluationPlanSerializer` for the response; one `workflow_preset.applied`
  audit event per apply.
- `StageBuilder` gets an "Apply a workflow preset" picker, shown only
  while the event has zero stages; it disappears once a preset (or a
  manually added stage) exists.

## Verification
- Backend: `pytest` full suite 588 passed/8 skipped; new
  `tests/integration/test_workflow_presets_api.py` (5 tests: preset list,
  graph/plan creation shape, reject-on-existing-stages, unknown preset,
  permission).
- `ruff check`/`ruff format --check`, `makemigrations --check` (no model
  changes), `openapi`/SDK check: clean (regenerated for the two new
  endpoints).
- Frontend: `pnpm test` 75 passed (1 new interaction test), `tsc --noEmit`,
  `vite build`, `pnpm format:check`: clean except the pre-existing,
  out-of-scope `master/worker_prompt.md` finding.

## Limitations
- Per-round pool assignment, prize judging, and rubric criteria stay
  explicit organizer decisions made afterward through the existing
  stage/plan endpoints, as designed -- a preset only shapes the graph.
