## Cross-cutting checks

- Authorization and visibility: the only server changes are two additive read-only fields or parameters (the audit read's `mine` and `limit`, the events lists' `phase`), each tested for who may read them. Everything else reads existing endpoints that already authorize; a judge or participant is offered no organizer-only control (tested in the browser).
- Migration and compatibility: no model, migration or stored value changed; OpenAPI and both SDKs were regenerated and `make verify-fast` checks them. Device-local keys are new and versioned (`conflux:v1:`); legacy URLs still redirect.
- States and viewports: every new overlay is tested inside the 390 viewport and with axe; the inspector at 1440, 1100, 800 and 390; loading, empty, error and long-list states are in component tests.
- Regressions found and fixed during this verification: the phase made two existing judge and participant event-list assertions exact-match (updated to read the new field); the inspector's phone sheet and the new floating layers joined the visual ratchet allowlist with their tokens; the header on a phone squeezed the event switcher to a chevron once Search and the bell were added (the brand word now gives its room on phones); a half-typed G chord was lost when the shell re-rendered, and Ctrl+K could be pressed a frame before its listener existed (both listeners now live in a ref and a layout effect, each with a regression test); isolated specs that set their own viewport now skip the mobile project.
