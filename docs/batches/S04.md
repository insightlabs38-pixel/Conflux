# S04 — Assignment simulator
## Result
Complete. Organizers can preview coverage/load/conflict/expertise/connectivity for one or more candidate coverage values before activating an assignment, which is otherwise immutable once created.
## Changes
- `evaluations/assignment.py`: extracted `_build_evidence` (shared by `activate` and the new `preview`) so both paths compute identical coverage/load/conflict/connectivity evidence from the same pure `compute_assignment`. `preview(plan, coverage=N)` runs the exact assignment algorithm with zero DB writes.
- New organizer-only `POST .../evaluation-plans/<id>/assignments/preview/` accepting `coverage_options` (1-10 positive integers, default `[3]`), returning one evidence dict per value.
## Verification
- New `tests/integration/test_assignment_preview.py` (5): preview evidence matches what `activate` actually freezes, a poolless plan's `ValueError` surfaces as a 400, multi-value comparison writes nothing (`assignment_versions.count() == 0`), input validation, and organizer-only access.
- Full suite: 485 passed, 8 skipped (was 480/8); `ruff format`/`check`, `manage.py check`, `makemigrations --check` (no migration needed), OpenAPI artifact check, `pnpm build`/`test` all clean.
## Limitations
- No organizer frontend yet (API-only, same as S01-S03).
