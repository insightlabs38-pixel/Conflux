# C-B22 — Canonical import/export and compatibility
## Result
Complete. Organizers can export an event's configuration as a versioned, deterministic archive and import it as a new event, with explicit validation and no bypass of domain invariants.
## Changes
- `integrations.archive`: `build_archive`/`import_archive` (PORT-001..003) — `format_version: 1`, public_id-based local refs remapped fresh on import, `config`/`full` modes, every row validated via its own model's `full_clean()`.
- New organizer routes: `GET .../events/<event>/archive/?mode=`, `POST workspaces/<workspace>/archive/import/`.
- `docs/architecture/CANONICAL_ARCHIVE.md` (PORT-005): scope, ref/versioning contract, and an explicit list of what v1 omits and why.
## Verification
- `pytest -q tests/compatibility/test_canonical_archive.py tests/integration/test_archive_api.py` → 13 passed, incl. PORT-004 roundtrip semantic-equivalence tests (config and full) and rejection tests for a bad `format_version`, a dangling ref, a missing full-mode user, and a smuggled invalid domain value.
- Full backend suite → 380 passed, 3 skipped. Ruff, Django check, makemigrations --check, OpenAPI artifact check → all clean.
## Limitations
- v1 config/full scope intentionally excludes submissions, stage entries, form responses, award winners/fulfillment, evaluation/community activity, and team assignment — see the doc's "does not cover" section.
- Evaluation-sourced awards import by evaluation-plan name; the plan itself isn't exported, so the target event must already have a matching plan.
