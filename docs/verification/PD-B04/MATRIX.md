## T08: route and draft preservation (closes the matrix)

Every capability above has at least one executable proof in its row. The table below is the cross-cutting regression for the four behaviours T08 names, run against real persisted data (`tests/e2e/route-drafts.spec.ts`, isolated-mutation tier, one `iso-min` fixture) with unit-level proofs beside it.

| Behaviour                            | Proof (positive)                                                                                                                                                                     | Boundary / negative                                                                                                                                     | Role / authorization                                                                                                                                       |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Unsaved draft across views + history | participant project story, organizer create-event form, judge ballot comment all keep their text through view changes, Back and Forward; the same entry reopens with the draft (e2e) | judge autosave writes the server draft, refresh + reopen restores it; a view change never clears an unsaved field                                       | drafts live in the same tab only; nothing reads another account's draft                                                                                    |
| Direct links and refresh             | refresh on a participant project view and on a judge queue reopens the same URL, event and view (e2e)                                                                                | a view the role does not have is replaced by the overview with no history entry; Back does not return to it                                             | participant `/operations` is replaced; judge queue URL opened as a participant is replaced by the overview and no judging region renders                   |
| Back/Forward with event context      | organizer `event=` survives setup, judging and results and both history directions (e2e)                                                                                             | panel state is dropped between views (`carriedSearch`), context stays                                                                                   | unchanged server authorization                                                                                                                             |
| Role change in one tab               | sign out, sign in as another role: nothing from the first account is on screen, and its view URL is replaced (e2e); per-session query reset (T02)                                    | previous judge's draft text is not rendered for the participant                                                                                         | **defect found and fixed (ESC-20260930-001, P1):** the offline judge outbox/cache were keyed by plan only, so queued ballots replayed under the next judge |
| Offline judge buffer                 | queued ballot survives refresh for its owner and syncs when that account signs back in with the network reachable (e2e; `JudgeWorkspace.offline.test.tsx`)                           | a second judge on the same browser and plan sees no queue and issues no ballot POST; legacy unscoped entries are neither read, replayed nor deleted (A) | keys are `conflux.judge-{outbox,cache}.<user>.<plan>`; with no known account nothing is stored                                                             |

Commands: `pnpm --filter @conflux/web test`; `scripts/e2e-tiers run isolated-mutation`; `make e2e-fast`. Stress: six concurrent fresh fixtures, 36/36 passed (`logs/T08-route-drafts-stress.log`). Repeating the spec against one shared fixture fails the judge tests by design (the first repeat submits the ballot), so repeats use a fixture each.

Limitations: selection state inside panels (judge project, builder item, tabs) is still local and is not part of the URL (T04/T07). Pre-upgrade unsent judge ballots stay in localStorage unattributed; owner may choose adoption or a prompt (ESC-20260930-001).
