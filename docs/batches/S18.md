# S18 — Configuration history/diff

## Result
Complete. Organizer mutations to event settings, stages, temporal gates, and
published rubrics now record a field-level before/after diff, readable
through a new event-scoped history endpoint and organizer dashboard panel.

## Changes
- `audit.services.snapshot_fields`/`diff_snapshots`: JSON-safe before/after
  snapshots and diffing, reused by every call site below (no per-domain
  reimplementation).
- Event settings (`EventDetailView.patch`), stage updates, and temporal gate
  updates attach a `changes` dict to their existing `record_mutation` call;
  a no-op patch (submitted value equals current value) records no changes.
- Rubric publish diffs the new version's `criteria` against the plan's prior
  published version (`None` on first publish, matching immutability).
- New `GET /api/v1/audit/<workspace>/events/<event>/config-history/`
  (organizer/admin only): newest-first, omits any audit row without a
  captured diff (including creates/deletes and pre-S18 rows) rather than
  inventing one. Scoped via `metadata__event_id`, the same JSON-key
  convention `CommunityAuditView` already uses.
- New `ConfigHistoryPanel` on the organizer event dashboard renders each
  entry's changed fields as JSON (policy ASTs and rubric criteria stay
  inspectable, per the design contract).

## Verification
- Backend: `pytest` full suite 576 passed/8 skipped; new
  `tests/integration/test_config_history_api.py` (7 tests: diff capture,
  no-op suppression, event scoping/ordering, permissions).
- `ruff check`/`ruff format --check`, `makemigrations --check` (no model
  changes), `openapi`/SDK check: all clean (openapi.yaml + generated SDKs
  regenerated for the new endpoint).
- Frontend: `pnpm test` 74 passed (3 new), `tsc --noEmit`, `vite build`:
  clean. `pnpm format:check` clean except the pre-existing, out-of-scope
  `master/worker_prompt.md` finding (not this product's file).

## Limitations
- Scope is exactly the contract's four domains (event settings, stages,
  temporal gates, published rubrics) via their existing update endpoints;
  Policy/PolicyBinding/Track/BasePrize stay create/delete-only and are
  unaffected, matching current product behavior.
