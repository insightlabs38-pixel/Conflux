# S02 — Judge calibration rounds
## Result
Complete. Organizers can designate a shared set of calibration projects a plan's judges must score against the rubric's anchors before live judging opens.
## Changes
- `EvaluationPlan.calibration_projects` (M2M, organizer-managed) and `calibration_required`; `Ballot.is_calibration` flags a calibration ballot and is mutually exclusive with real-candidate membership (`Ballot.clean`) so a project is never both.
- New endpoints under `.../evaluation-plans/<id>/`: `calibration-projects/` (judge-readable, organizer-writable), `calibration/ballots/` (reuses `Ballot`/`BallotResponse` and their validation, isolated per judge), `calibration/status/` (own or, for an organizer, any judge's completion), `calibration/summary/` (organizer-only raw per-criterion scores + min/max/mean/spread, explicitly not the formal agreement analytics S03 will add).
- `BallotListCreateView.post` now blocks real ballot submission while `calibration_required` and the judge has projects left; `scoring.ballot_observations` and `progress.compute_progress` exclude calibration ballots from normalization and completion counts (the latter was a latent double-count bug fixed here).
- `JUDGING.md`-adjacent scope note left in code comments; no separate doc section added (S02 doesn't touch the normalization method itself).
## Verification
- New `tests/integration/test_calibration_api.py` (9): project designation, ballot marking/isolation, mutual-exclusion with live candidates, the live-judging gate (blocked → unblocked), per-judge status isolation, raw summary spread, and normalization/progress exclusion.
- Full suite: 468 passed, 8 skipped (was 459/8); `ruff format`/`check`, `manage.py check`, `makemigrations --check`, OpenAPI artifact check, `pnpm build`/`test` all clean.
## Limitations
- No organizer/judge frontend yet (API-only, same as S01).
- `calibration/summary/` is raw evidence, not a statistical agreement measure — S03 owns that.
