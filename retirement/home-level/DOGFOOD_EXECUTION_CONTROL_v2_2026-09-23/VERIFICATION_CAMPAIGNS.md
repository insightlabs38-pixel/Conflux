# Freebuff-Heavy Verification Campaigns

Run continuously behind implementation, normally 1–2 campaigns at a time.

- V-AUTH: role × event × resource owner × endpoint × action × auth state.
- V-POLICY: AST generation, depth/type/missing facts, determinism, fail-closed, explanation consistency.
- V-STAGE: DAG mutations/cycles/branch-merge/advancement/stage team rules.
- V-FORM: field/version/conditional/visibility/property tests.
- V-ARTIFACT: upload intent/completion/object metadata/type/size/expiry/malformed cases.
- V-SUBMISSION: deadline ± boundary, exception states, idempotency, concurrent finalization, stale artifacts.
- V-JUDGING: assignment constraints/coverage/load/conflicts/order invariance.
- V-NORMALIZATION: constant/sparse/extreme/missing/disconnected/reordered fixture mutations.
- V-COMMUNITY: vote identity modes, duplicates, randomization, windows, result hiding, comments.
- V-AWARDS: eligibility/stacking/conflict/fulfillment state machine.
- V-API: schema/negative auth/malformed/bulk behavior.
- V-WEBHOOK: signature/retry/replay/SSRF/failure/reordering/idempotency.
- V-IMPORT: roundtrip, missing/unknown/reordered/duplicate/corrupt/large/future fields.
- V-PRESENTATION: raw gallery checker content, sanitization, responsive/accessibility.
- V-MIGRATION: migrate from prior fixture, upgrade/downgrade expectations where supported.
- V-E2E: organizer→participant→judge→publish flows.
- V-LOAD: baseline/deadline/judging/voting/gallery scenarios.

Frontier models review large gates or unusual failures rather than writing every permutation.
