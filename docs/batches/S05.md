# S05 — Mid-event judge rebalancing
## Result
Complete. An organizer can recover an assigned-subset plan's active assignment after judge dropout or backlog: dropped judges' pending load is reassigned, already-submitted ballots are never disturbed, and connectivity is re-repaired.
## Changes
- `evaluations/assignment.py::rebalance(plan, *, drop_judge_ids, coverage=None)`: keeps every already-submitted `Ballot`'s pairing regardless of drop status, drops each dropped judge's pending pairings, tops projects back up to coverage from the remaining pool (same least-loaded/track-fit/id tie-break rule as `compute_assignment`), reruns `repair_connectivity`, and freezes a new `AssignmentVersion` via the shared `_build_evidence` helper (from S04) with `rebalanced_from`/`dropped_judges` added to its evidence.
- New organizer-only `POST .../evaluation-plans/<id>/assignments/rebalance/` (`drop_judges`: judge public_ids, `coverage`: optional override).
- Only applies to `ASSIGNED_SUBSET`; raises for `ALL_JUDGES` or a plan with no active assignment yet.
## Verification
- New `tests/integration/test_assignment_rebalance.py` (6): submitted work survives a drop, pending work is reassigned and coverage restored, cross-fixture determinism (by relative judge/project position) plus a real connectivity check, the two `ValueError` guard rails, the API round trip (audit event, evidence shape), and organizer-only access.
- Full suite: 491 passed, 8 skipped (was 485/8); `ruff format`/`check`, `manage.py check`, `makemigrations --check` (no migration needed), OpenAPI artifact check, `pnpm build`/`test` all clean.
## Limitations
- No organizer frontend yet (API-only, same as S01-S04).
- A judge's own already-submitted ballots outside the current active version's coverage window (e.g. from a much older version) are not considered "kept" evidence for coverage counting — only the version being rebalanced.
