## Cross-cutting checks

- Authorization and visibility: the two server changes (`group`, `subgroup`) are inside the entity's own rows and roles and are tested like the rest; saved views keep their rules (owner changes, sharing widens who sees a definition, never rows).
- Migration and compatibility: no model or migration. A view definition may carry `group`, `subgroup` (stored only when used) as it may carry `search`; older views round-trip unchanged. OpenAPI and both SDKs regenerated and checked by `make verify-fast`. New address params (`f_`, `group_`, `then_`) are ignored by older builds.
- States and viewports: every spec runs at desktop and the 390 mobile project or says why not; loading, empty, refused and truncated states are in unit or browser tests; axe on each surface.
- Regressions found and fixed during this batch: the visual ratchets (not run since B01) rejected a box shadow, a content string and a raw weight from B01 and B02-T01 CSS; a B01 spec asserted that the phone has no header row, which B02-T01 deliberately changed; several earlier tests encoded limits this batch lifts (a nested filter cannot be edited, a range typed as a list, a date typed as text) and were updated with the same intent.
