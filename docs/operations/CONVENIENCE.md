# Operator and participant conveniences (PVS17)

| Feature                      | Route (`…/workspaces/{ws}/events/{e}/`)                                                              | Notes                                                                                                                                                                                                                                                                                                                                                                                                         |
| ---------------------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Maintenance (read-only) mode | `maintenance/` GET (members) / PUT (organizer) `{read_only, message}`                                | While on, every API **write** scoped to the event answers `503` + `Retry-After` for everyone except that workspace's organizers/admins (so a backup restore or migration can run safely). Enforced centrally after each view's own permission checks, so 401/403/404 still win and no route can opt out; a test walks every event-scoped write route. Reads, other events and background jobs are unaffected. |
| Gallery visibility           | `projects/{p}/visibility/` GET / PUT `{gallery_visible}` (member) or `{blocked, reason}` (organizer) | A team can hide its project from every public surface (gallery, search, project page, results stories, expo map); an organizer block overrides the team's choice and needs a reason. Default visible; portfolio and judging are unaffected. Fields are in the final archive.                                                                                                                                  |
| CSV import preview           | `imports/projects-csv/preview/` POST `{csv_text, mapping?}` (organizer)                              | Suggests a column mapping from common header names, then reports per-row problems (blank/duplicate name, owner not in the workspace, unknown track) and the count that would import. Read-only: writes nothing. 1 MB / 2000 rows. The actual import remains the existing CSV → archive → import path.                                                                                                         |
| Participant self-export      | `my-data/export/` GET                                                                                | The caller's own data in this event (same exporter and audit as the organizer's subject export). Erasure stays organizer-controlled.                                                                                                                                                                                                                                                                          |

Not built (already covered or wrapper-only): permission preview (Permission Matrix explorer / `authz` dry-run) and clone preview (event templates panel); deep links use the existing `?workspace=&event=` URLs.
