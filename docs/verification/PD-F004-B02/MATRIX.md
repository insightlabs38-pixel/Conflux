## State and viewport coverage

- Normal, loading, empty, error and denied states: each has a component test, a ratchet and a live check at 390 and 1440 (T03-T05); partial success naming the parts is BULK_PLAN's result and unchanged.
- Dense: the disclosure and status rules hold on the dense entity grid; density tokens are PD-F005.
- Mobile: hero band at most 120px, touch targets 44px (B01), disclosures keep the 24px target-size floor (axe passes in `workspace-shell` on every organizer destination at 390, 768, 1024, 1440).
- Public: `public`, `showcase`, `foundations`, `event-themes`, `hero-size`; axe and no horizontal overflow.

## Authorization, lifecycle, concurrency, migration

- Authorization: the only mutation added is the existing page PATCH with one more enum; the organizer-only check, validation and 400 on refusal are the existing ones (`test_page_builder_api.py`, `test_event_themes.py`).
- Lifecycle and concurrency: no new state; the page's existing version/audit path is unchanged.
- Migration and compatibility: none needed; a theme stored before `hero_size` existed has no key and renders compact (tested). Visible consequence: events with a stored theme now show the compact hero by default.

## Defects found by this batch's verification (fixed in the product, nothing relaxed)

- Eligibility queue at 390 scrolled the page sideways by 57px: a `position: absolute` visually-hidden header escaped its static scroll region (found by `workspace-shell`, fixed in `.cx-scroll-region`, ratchet added).
