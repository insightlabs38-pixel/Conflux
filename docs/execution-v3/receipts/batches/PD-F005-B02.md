# PD-F005-B02 — Application shell, second slice: state, recents, pins, roles, preview, inspector, keys, density
## Result
All 10 tasks DONE (T01-T08, T90, T91; this batch has no T00 or T95). The shell now says where an event is in its life (draft, open, closed, judging, published, archived), offers recent actions and views and pinned views in the palette, lets a person who holds several roles view as one (a choice of screen, never a permission), previews what a participant, judge or the public would see (read-only, over PREVIEW_CONTEXT), opens any list record in an inspector beside the list, has a shortcut help with G-then-letter navigation and a WCAG 2.1.4 off switch, and a per-person table density.
## Changes
- Two additive read-only API changes, recorded in spec 005: `phase` on the organizer, judge and participant event lists (`events/lifecycle.py`) and `mine` and `limit` on the audit read; OpenAPI and both SDKs regenerated and checked. No model, migration or stored value.
- Device-local, validated, cleared at sign-out: pins, recent views and commands, theme, density, shortcut switch (`lib/shellPreferences.ts`).
## Verification
- `make verify-fast` (pytest 2955, vitest 802, lint, build, openapi and sdk clean) then `make e2e-fast` (read-only 320 passed, every isolated spec and the canary chain ok), each run alone; logs, `MATRIX.md`, `SURFACES.md` in `docs/verification/PD-F005-B02/`; docs in VISUAL_FOUNDATION.md, UPGRADES.md and spec 005 "As built".
## Findings
- Owner questions logged with conservative defaults (QUESTIONS.md): the default density and its heights, what "preview as" means, how judging and published are defined.
- Caught and fixed by verification: a half-typed G chord dropped on re-render, Ctrl+K pressed a frame before its listener, the phone header squeezing the event switcher, two exact-match event-list tests, the visual ratchet allowlist; verify-fast and e2e-fast are run one after the other.
## Limitations
- Shell preferences follow the device, not the person. Judging is read from submitted ballots, not a window. Only the form and the public page can be previewed. The inspector is read-only and steps within a page. The slop audit still does not walk dialogs. Reviewed by the single implementing agent.
