# PD-B04-T01 — application route hierarchy

Source of truth: `src/web/lib/routes.ts` (builders, base path, `legacyTarget`) and `src/web/app/App.tsx` (route table). Router: `react-router` 8 (declarative `BrowserRouter`, basename `/app` behind the gateway, `` on the Vite dev server and in tests; a `StaticRouter` without `window`).

| Route                   | Renders                                                                                                                                                           | State in the URL                                            |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| `/`                     | workspace selector / sign-in; legacy query URLs are redirected here                                                                                               | none                                                        |
| `/w/:workspaceId`       | redirect (replace) to `/w/:workspaceId/overview`                                                                                                                  | keeps `?event=`/`?invite=`                                  |
| `/w/:workspaceId/:view` | role workspace (`TeamWorkspace`, `JudgeWorkspace`, `StaffWorkspace`, `EventDashboard`); `:view` ∈ the role's `roleDestinations`, otherwise replaced by `overview` | `?event=<id>` selected event, `?invite=<token>` team invite |
| `/person/:personId`     | public person profile                                                                                                                                             |                                                             |
| `/event/:eventId`       | public event site (no session)                                                                                                                                    |                                                             |
| `/api-explorer`         | API explorer (lazy chunk)                                                                                                                                         |                                                             |
| `*`                     | "That page does not exist." with a link home                                                                                                                      |                                                             |

Behavior: one workspace component stays mounted while `:view` changes, so `Destination` keeps hidden drafts/offline buffers alive (unchanged contract); destination links are router links (plain click = in-app push, modified click = browser new tab, `href` = canonical deep link); back/forward/refresh are the browser's; unauthenticated deep links show the sign-in form on the same URL and resume there (previously an "Could not check workspace access" error).

## Compatibility (old URLs keep working, via `replace`, no extra history entry)

| Legacy                                                            | Canonical                                      |
| ----------------------------------------------------------------- | ---------------------------------------------- |
| `/app/?workspace=W`                                               | `/app/w/W/overview`                            |
| `/app/?workspace=W&view=V`                                        | `/app/w/W/V`                                   |
| `/app/?workspace=W&view=V&event=E&invite=T`                       | `/app/w/W/V?event=E&invite=T`                  |
| `/app/?person=P` (emitted by the API as `profile_url`, unchanged) | `/app/person/P`                                |
| `/app/?event=E` (no workspace)                                    | `/app/event/E`                                 |
| `/app/?api=explorer`                                              | `/app/api-explorer`                            |
| `/?<any of the above>`                                            | gateway `302 /app/?<query>` then the row above |

Precedence as before: API explorer, person, public event, workspace. Invite links generated by the team panel now use `/app/w/W/team?event=E&invite=T`.

## Server change (outside the owned paths, inseparable)

`infra/Caddyfile`: `@app path /app /app/*` (was `/app /app/`), so every client route gets the shell on a hard load; verified through the gateway (`routing.spec.ts` loads nested paths directly). The API, `profile_url` and Django routes are unchanged; built assets still come from `/static/app/`. After changing the Caddyfile: `docker compose exec caddy caddy reload --config /etc/caddy/Caddyfile`.

## Known follow-ups (owned by later PD-B04 tasks)

Role resolution still calls `/accounts/me/` in both selector and workspace route (server-state layer, T02); `fetch` is still raw (typed client, T03); which filters/tabs belong in the URL beyond `event`/`invite` is T04; focus/announcement on history navigation beyond the existing main-content focus is untouched.
