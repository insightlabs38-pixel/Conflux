# PD-F002-B03 — Shared primitive: preview as a person, a version or a time
## Result
All 3 tasks DONE (T01, T90, T91; no T95). One reusable platform primitive, `PREVIEW_CONTEXT`, with a real adopter and an independent contract test; no migration.
## Changes
- A context (`role`, `at`, `version`) is request data, never an identity: one read-only endpoint `POST /workspaces/{id}/preview-as/{surface}/`, organizers and admins only, nothing stored or sent, no header, cookie or session carries it and a scan proves no other code reads it.
- Surfaces are code-owned and registered (roles they can be viewed as, an optional `core.version_diff` source, an optional schema-subset input); the primitive parses, picks the version by id or by time, names what it resolved and gives one sentence for the UI.
- Adopter: a saved form as a participant, judge, organizer or public, at a kept version or as of a time, in a closed form-builder section; visibility is the form's own rule (`field_in_scope` split out of `field_visible`, behavior unchanged). The extensions inventory gains a `preview_surface` capability.
