# PD-B02-T01 — Backend test tail and setup profile

Baseline (PD-B00-T02, SQLite, 8 xdist workers): 1400 passed/23 skipped, **78 s wall, 9m12s CPU**.

| Cost                                         | Evidence                                                                                                                                                                                                                                                                                                                                   | Share                                 |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------- |
| **Password hashing (Django default PBKDF2)** | Same suite with only `PASSWORD_HASHERS=[MD5]` (scratch settings, nothing committed): **27 s wall, 2m31s CPU**, 1401 passed/23 skipped → hashing ≈ **6m40s of 9m12s CPU (~73%)**. The slowest test call, `test_login_throttles_guessing_per_account_and_resets_on_success` (7.0 s ≈ 25 verifications × ~0.28 s), drops out of the top list. | dominant                              |
| Per-worker test DB creation                  | 101 migrations per worker DB: first-test `setup` = 6.3–8.2 s on every worker (8 workers in parallel, so ~7 s of wall). `--nomigrations` removes it but 1 test fails (depends on migration-created data) → not a safe blanket change.                                                                                                       | ~7 s wall (26% of the optimized 27 s) |
| Slowest remaining calls (baseline)           | 3.3 s `test_demo_scenarios`, 2.8 s `test_assignment_rebalance`, next all < 2.5 s                                                                                                                                                                                                                                                           | minor                                 |

Conclusion: the tail is not spread-out slowness; it is one systemic cost (production-strength password hashing on hundreds of throwaway users) plus fixed migration setup. Targets: T02 removes the hashing cost in tests only, keeping a guard that production settings still use the default strong hasher and one end-to-end test that authenticates with it; migration-setup reuse is evaluated after re-measuring.
